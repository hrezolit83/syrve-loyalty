# Syrve Loyalty — сервіс лояльності для закладів

Telegram-бот для гостя і веб-панель для адміністратора поверх програми лояльності **Syrve**: реєстрація гостя з видачею картки, QR-код і баланс у боті, ручні нарахування та списання бонусів із журналом, сповіщення про зміну балансу.

Баланс, картки й транзакції живуть у Syrve — сервіс їх не дублює, а працює з ними через Syrve Cloud API. Докладніше про розподіл даних і причини рішень — у [ARCHITECTURE.md](ARCHITECTURE.md). План розробки й усі відхилення від нього — у [docs/PLAN.md](docs/PLAN.md). Що зроблено, що перевірено і що ні — у [REPORT.md](REPORT.md).

---

## Швидкий старт

Потрібні лише **Docker** і **Docker Compose**.

```bash
git clone https://github.com/hrezolit83/syrve-loyalty.git
cd syrve-loyalty
cp .env.example .env     # заповнити значення, див. нижче
docker compose up --build
```

Піднімається п'ять контейнерів: `postgres`, `redis`, `api`, `worker` (бот + поллер) і `admin` (панель за nginx). Міграції бази й створення адміністратора виконуються автоматично перед стартом API — нічого запускати руками не потрібно.

| Що | Адреса |
|---|---|
| Панель адміністратора | http://localhost:8080 |
| API | http://localhost:3000/api |
| Перевірка живості | http://localhost:3000/api/health |
| Перевірка зв'язку з Syrve | http://localhost:3000/api/health/syrve |

Логін і пароль адміністратора — ті, що ви вписали в `ADMIN_LOGIN` і `ADMIN_PASSWORD`. Сід створює адміністратора при кожному старті через `upsert`, тому зміна пароля в `.env` + перезапуск = новий пароль.

Зупинити: `docker compose down`. Зупинити й **стерти дані** (база, Redis): `docker compose down -v`.

## Налаштування `.env`

Усі значення — лише в `.env`. Файл у `.gitignore` і в репозиторій не потрапляє; `.env.example` містить ті самі змінні з порожніми значеннями.

```ini
# ---------- HTTP ----------
PORT=3000
ADMIN_PORT=8080
VITE_API_URL=http://localhost:3000

# ---------- Логи ----------
LOG_LEVEL=info
LOG_PRETTY=true

# ---------- Syrve ----------
SYRVE_MODE=real
SYRVE_API_URL=https://api-eu.syrve.live
SYRVE_API_LOGIN=
SYRVE_ORGANIZATION_ID=
SYRVE_PROGRAM_ID=

# ---------- PostgreSQL ----------
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_DB=syrve_loyalty
POSTGRES_PORT=5432
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/syrve_loyalty?schema=public

# ---------- Redis ----------
REDIS_HOST=localhost
REDIS_PORT=6379

# ---------- Авторизація ----------
JWT_SECRET=
ADMIN_LOGIN=
ADMIN_PASSWORD=

# ---------- Telegram ----------
TELEGRAM_BOT_TOKEN=

# ---------- Поллер транзакцій ----------
POLL_INTERVAL_SEC=30
```

Що важливо знати:

- **`SYRVE_API_LOGIN`** — ключ доступу до Syrve Cloud API (`apiLogin`), його видає Syrve. Це секрет.
- **`SYRVE_PROGRAM_ID` треба задавати явно.** У наданій тестовій організації активні **чотири** програми лояльності, і без явного id сервіс візьме першу активну — бонуси можуть піти в гаманець не тієї програми. Дізнатися id: `node scripts/explore.js` (див. нижче).
- **`DATABASE_URL` і `REDIS_HOST`** у Docker перекриваються автоматично на `postgres` і `redis` — у `.env` їх можна лишати для локального запуску без Docker.
- **`JWT_SECRET`** — будь-який довгий випадковий рядок, наприклад `openssl rand -base64 32`.
- **`ADMIN_PASSWORD`** — не коротший за 8 символів, інакше сід відмовиться створювати адміністратора.

### Як отримати `TELEGRAM_BOT_TOKEN`

1. Напишіть у Telegram боту [@BotFather](https://t.me/BotFather).
2. Надішліть `/newbot`, далі — назву бота й унікальний username (мусить закінчуватися на `bot`).
3. BotFather надішле токен виду `1234567890:AA...` — це значення й вписується в `TELEGRAM_BOT_TOKEN`.

Без токена сервіс запуститься, але бот не стартує (у лог піде попередження `Telegram-бот вимкнений`) — панель, API і поллер працюватимуть.

### Запуск без доступу до Syrve

```ini
SYRVE_MODE=mock
```

У цьому режимі замість Syrve працює мок-клієнт із тим самим інтерфейсом. Дані (гості, картки, баланси, транзакції) лежать у таблицях `mock_customers` і `mock_transactions`. Мок повторює поведінку живого API, включно з числовими кодами типів транзакцій і тим, що **списання понад баланс не відхиляється** — див. ARCHITECTURE.

Ні `SYRVE_API_LOGIN`, ні `SYRVE_ORGANIZATION_ID`, ні `SYRVE_PROGRAM_ID` у мок-режимі не потрібні.

## Як перевірити кожну функцію

Нижче — покроково, руками. Для функцій О1 і О6 є ще автоматичні скрипти, вони описані в кінці.

### О1 — підключення до Syrve

Відкрийте http://localhost:3000/api/health/syrve

```json
{
  "status": 200,
  "message": "Підключення до Syrve працює",
  "data": {
    "mode": "real",
    "token": "отримано",
    "organization": { "id": "…", "name": "…" },
    "program": { "id": "…", "name": "…", "walletId": "…", "isActive": true }
  }
}
```

Токен у відповідь не потрапляє — лише факт, що його отримано. Якщо ключ не підійшов, буде `503` з українським текстом і `correlationId` Syrve.

Токен живе годину й оновлюється сам: за 5 хвилин до закінчення та при відповіді `401`. Перевірити це руками за одну сесію неможливо — логіка покрита в коді (`api/src/services/syrve/realClient.js`).

### О2 — реєстрація гостя в Telegram

1. Знайдіть свого бота в Telegram і натисніть **Старт** (або надішліть `/start`).
2. Бот попросить номер — натисніть кнопку **📱 Надіслати контакт**. Введений руками номер бот не прийме: Telegram підтверджує право на номер лише через кнопку.
3. Бот попросить ім'я — введіть його (2–50 символів, лише літери, пробіл, дефіс, апостроф).
4. Бот відповість номером картки й надішле QR-код.

Що ще перевірити:
- **Повторний `/start`** — бот одразу покаже меню, нового гостя й нової картки не створить.
- **Повторна реєстрація того самого номера з іншого Telegram-акаунта** — у Syrve залишиться один гість і та сама картка, а зв'язок перейде на новий акаунт.
- **Чужий контакт**: переслати боту контакт іншої людини — бот відмовиться (`contact.user_id` не збігається з відправником).

### О3 — картка й баланс

У меню бота:
- **💳 Моя картка** — QR-код номера картки, під ним номер і актуальний баланс.
- **🔄 Оновити баланс** — поточний баланс із Syrve.

Баланс читається з гаманця саме вашої програми (`walletId` з `SYRVE_PROGRAM_ID`), а не сумою по всіх програмах гостя.

### О4 — панель адміністратора

1. Відкрийте http://localhost:8080 — без входу будь-яка сторінка перекидає на форму входу.
2. Увійдіть із `ADMIN_LOGIN` / `ADMIN_PASSWORD`.
3. На сторінці **Пошук** введіть телефон гостя в будь-якому звичному вигляді: `+380XXXXXXXXX`, `0XXXXXXXXX`, `380XXXXXXXXX` або з пробілами.
4. Побачите ім'я, телефон, номер картки, баланс і позначку, чи підключений у гостя Telegram.

Що ще перевірити:
- **Неіснуючий номер** → «Гостя з таким телефоном не знайдено».
- **Сміття замість номера** → підказка про формат.
- **Вихід** («Вийти») → сторінки знову недоступні.
- **Захист від перебору пароля**: 10 невдалих спроб входу за хвилину → `429` з українським текстом.

### О5 — ручне нарахування і списання

На картці гостя — блок **«Нарахування та списання»**:

1. Виберіть **Нарахувати** або **Списати**.
2. Введіть суму (до двох знаків після коми) і причину (3–200 символів) — обидва поля обов'язкові.
3. Підтвердіть дію у вікні підтвердження.
4. Баланс і журнали оновляться самі.

Що ще перевірити:
- **Списати більше, ніж є на балансі** → `409` «Недостатньо бонусів: на балансі …, списати …». Операція не виконається. Це перевірка **нашого** сервісу: сам Syrve списання понад баланс дозволяє.
- **Сума 0 або з трьома знаками після коми, причина з двох символів** → помилки валідації українською.
- **Журнал «Історія операцій»** під формою: хто, коли, скільки, чому, результат. Невдалі спроби теж записані — у рядку буде позначка «відмова», а текст помилки видно при наведенні.

### О6 — сповіщення про бонуси

Потрібен гість, зареєстрований через бота.

1. **З панелі:** нарахуйте йому бонуси → протягом `POLL_INTERVAL_SEC` (за замовчуванням 30 с) у Telegram прийде «✅ Нараховано N бонусів. Баланс: M».
2. **З кабінету Syrve Loyalty:** змініть баланс того самого гостя напряму в кабінеті → прийде таке саме повідомлення. Саме для цього сервіс опитує Syrve, а не покладається на власні операції.
3. **Без дублів:** одна операція — одне повідомлення. Перезапуск воркера (`docker compose restart worker`) повторних повідомлень не викликає.

Напрямок повідомлення («нараховано» чи «списано») визначається знаком суми транзакції, тому новий, невідомий сервісу тип операції Syrve все одно буде описаний правильно.

### Д1 — історія операцій

- **У боті:** кнопка **📜 Історія** — останні 10 змін балансу: дата, сума зі знаком, баланс після, коментар.
- **У панелі:** на картці гостя блок **«Операції в Syrve»** — останні 20 змін балансу, з назвою типу операції Syrve.

Це саме дані Syrve, тому видно й нарахування з каси та правки з кабінету, про які сервіс сам нічого не знає. Блок «Історія операцій» — інше: це наш журнал ручних операцій панелі, з причинами й невдалими спробами.

### Д2 — список гостей

Сторінка **Гості** в панелі:
- усі гості, зареєстровані через бот;
- пошук за іменем, телефоном або номером картки;
- сортування за датою реєстрації та іменем (клік по заголовку стовпця перемикає напрямок);
- пагінація по 20;
- клік по імені → картка гостя з усіма операціями.

Сортування за іменем українське: `Андрій, Богдана, Василь, …, Ігор`, а не стандартний порядок PostgreSQL, де латиниця йде перед кирилицею.

## Автоматичні перевірки

```bash
# Робота з живим Syrve: пошук, реєстрація, ідемпотентність,
# нарахування/списання, захист від мінусового балансу, синхронізація
cd api && node scripts/check-syrve-real.mjs

# Надійність сповіщень О6: без дублів, рестарт воркерів, зміна з кабінету,
# невідомий тип транзакції, блокування бота
cd api && node scripts/check-notifications.mjs
```

`check-syrve-real.mjs` створює тестового гостя `+380991000002` у вашій організації Syrve, повертає його баланс до нуля й прибирає свої записи з бази. `check-notifications.mjs` працює в мок-режимі й підміняє лише відправку в Telegram — поллер, черги, база й воркери справжні.

Розвідка API (зберігає зразки відповідей у `docs/api-samples/`, замінивши секрети на `<redacted>`):

```bash
node scripts/explore.js                  # токен, організації, програми
node scripts/explore.js --with-customer  # + гість, картка, баланс, транзакції
```

## Локальний запуск без Docker

Потрібні Node.js 22+, PostgreSQL і Redis.

```bash
# база й Redis — найпростіше все одно в Docker
docker compose up -d postgres redis

cd api
npm install
npx prisma migrate deploy
npm run seed          # адміністратор із .env
npm run dev           # API
npm run dev:worker    # в іншому терміналі: бот + поллер

cd ../admin
npm install
npm run dev           # панель на http://localhost:5173
```

У режимі розробки панель ходить до API через проксі Vite (`/api` → `VITE_API_URL`), тому cookie з JWT працює без налаштувань CORS.

## Структура

```
api/                 Node.js + Express 5
  prisma/            схема й міграції
  scripts/           автоматичні перевірки
  src/
    bot/             Telegram-бот (grammY)
    constants/       константи, мапінг типів транзакцій
    controllers/     обробники запитів
    db/              клієнт Prisma
    middlewares/     автентифікація, валідація, лімітер, помилки
    queues/          черги BullMQ
    routers/         маршрути
    services/        бізнес-логіка, клієнт Syrve (real + mock)
    templates/       тексти повідомлень бота
    utils/           телефон, QR, номер картки, логер
    workers/         поллер транзакцій і відправка сповіщень
admin/               React + Vite + TypeScript, nginx у Docker
docs/                план, умова завдання, зразки відповідей API
scripts/explore.js   розвідка Syrve API
```
